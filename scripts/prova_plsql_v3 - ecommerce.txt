AVALIAÇÃO PRÁTICA — PL/SQL
Estudo de caso aplicado em um e-commerce — "ShopFast"
Trabalho em grupo (3 a 5 alunos) — entrega via Portal do Aluno
1. Objetivo
Avaliar a capacidade do grupo de aplicar, em conjunto, os principais recursos da linguagem PL/SQL — bloco anônimo, variáveis, estruturas condicionais, estruturas de repetição, cursores explícitos, procedures, functions e tratamento de exceções — para resolver problemas reais do dia a dia operacional de um e-commerce.
Os exercícios estão encadeados: a solução de um exercício é insumo para os seguintes. O grupo deve construir progressivamente um conjunto de objetos PL/SQL que, ao final, permitam executar o fluxo completo de uma compra.
2. Preparação do ambiente
O schema da ShopFast (tabelas, sequências, índices e dados de teste) está disponibilizado no arquivo prova_plsql_setup.sql, fornecido junto com este enunciado. Antes de iniciar os exercícios, cada integrante deve executar este script no seu schema Oracle. O script é idempotente — pode ser reexecutado para limpar e recarregar o ambiente quantas vezes forem necessárias.
Após a execução, o schema conterá as 12 tabelas com prefixo cp3_, todas em 3ª Forma Normal, populadas com clientes, endereços, CEPs, fornecedores, produtos, estoques, pedidos e pagamentos suficientes para validar todos os exercícios. Em particular, há um pedido em status PENDENTE, que será utilizado para validar os exercícios 8 e 10.
3. Estudo de caso — "ShopFast"
A ShopFast é um e-commerce brasileiro de produtos diversos (eletrônicos, livros, alimentos não perecíveis e vestuário). A operação envolve cadastro de clientes com múltiplos endereços, catálogo organizado por categoria, controle de estoque com histórico de movimentações, pedidos com itens e pagamento, cálculo de frete por região e classificação de clientes conforme volume de compras.
A equipe de TI precisa automatizar diversas rotinas operacionais no banco Oracle. A direção pediu que o grupo desenvolva os scripts e objetos PL/SQL descritos nos exercícios da Seção 5.
4. Regras gerais e restrições técnicas
•  Todos os objetos criados pelo grupo (procedures, functions) devem ter o prefixo cp3_ no nome (ex.: cp3_fn_total_pedido, cp3_pr_finalizar_pedido).
•  É PROIBIDO o uso de SYS_REFCURSOR. Quando precisar percorrer um conjunto de linhas com lógica adicional, declare seu próprio cursor explícito (CURSOR ... IS SELECT ... com OPEN/FETCH/CLOSE ou cursor FOR LOOP).
•  É PROIBIDO o uso de cursores ou views do dicionário do sistema (USER_*, ALL_*, DBA_*) como base dos exercícios. Toda lógica deve trabalhar sobre as tabelas do schema da ShopFast.
•  Variáveis devem ser declaradas explicitamente (preferencialmente usando %TYPE ou %ROWTYPE quando aplicável).
•  Tratamento de exceções: criar exceções nomeadas com PRAGMA EXCEPTION_INIT ou usar RAISE_APPLICATION_ERROR com códigos no intervalo −20000 a −20999. Mensagens de erro devem ser claras e em português.
•  Cada procedure ou function deve ter um cabeçalho em comentário com: nome, autor, data, parâmetros e descrição.
•  Nenhum exercício admite hard-code de valores que dependam dos dados (use parâmetros de entrada ou variáveis).
•  Apenas o exercício 1 é um bloco anônimo. Todos os demais são procedures ou functions criadas no schema (CREATE OR REPLACE).
•  Os blocos anônimos e os scripts de teste devem usar DBMS_OUTPUT.PUT_LINE para exibir resultados.
5. Exercícios
Os 10 exercícios a seguir estão encadeados: cada um utiliza algum objeto criado no anterior. Resolva-os em ordem. Cada solução deve ser entregue como um arquivo .sql separado (ex01.sql até ex10.sql), além de um script de testes para cada exercício (test_ex01.sql até test_ex10.sql) que demonstre a execução.
Exercício 1 — Verificação rápida de estoque
Tipo de objeto: bloco anônimo
Recursos PL/SQL exigidos: DECLARE/BEGIN/END, variáveis, IF/ELSE, DBMS_OUTPUT
A equipe de operações precisa verificar rapidamente a situação de estoque de um produto específico. Escreva um bloco anônimo que receba o ID do produto via variável de substituição (&produto_id) e exiba, em uma única linha:
•  o nome do produto;
•  o nome da categoria a que ele pertence;
•  a quantidade atualmente em estoque;
•  a quantidade mínima cadastrada;
•  a mensagem ALERTA: REPOR ESTOQUE quando a quantidade atual for inferior à mínima, ou ESTOQUE OK caso contrário.
Se o produto informado não existir, o bloco deve sinalizar isso de forma clara (sem deixar exceção não tratada). Este é o único exercício do trabalho que é um bloco anônimo — todos os demais são objetos persistentes (procedures e functions) criados no schema.
Exercício 2 — Procedure: relatório de produtos por categoria
Tipo de objeto: PROCEDURE
Recursos PL/SQL exigidos: parâmetros IN, estrutura de repetição (LOOP / FOR / WHILE), DBMS_OUTPUT
Crie a procedure cp3_pr_listar_produtos_categoria(p_categoria_id IN NUMBER) que exiba, para cada produto ATIVO da categoria informada: nome do produto, preço unitário e quantidade em estoque. Utilize uma estrutura de repetição para iterar sobre o conjunto resultante. Ao final, mostre o total de produtos listados. Se a categoria não existir, lance uma exceção customizada.
Exercício 3 — Procedure: pedidos de um período
Tipo de objeto: PROCEDURE
Recursos PL/SQL exigidos: cursor explícito (CURSOR ... IS SELECT, OPEN/FETCH/CLOSE)
A área comercial pediu um relatório dos pedidos realizados em um intervalo de datas. Crie a procedure cp3_pr_listar_pedidos_periodo(p_data_ini IN DATE, p_data_fim IN DATE) que, para cada pedido do período, exiba: número do pedido, data, nome do cliente e status. Como cada linha receberá tratamento adicional no próximo exercício, declare e manipule um cursor explícito (não use cursor FOR LOOP automático nesta etapa — utilize OPEN, FETCH e CLOSE explicitamente). Valide que p_data_fim ≥ p_data_ini, lançando exceção em caso negativo.
Exercício 4 — Procedure: detalhamento dos itens de cada pedido
Tipo de objeto: PROCEDURE
Recursos PL/SQL exigidos: cursores aninhados, variáveis, cálculo aritmético
Aprofunde o relatório do exercício 3: crie a procedure cp3_pr_detalhar_pedidos_periodo(p_data_ini IN DATE, p_data_fim IN DATE) que, para cada pedido encontrado no período, exiba também o detalhe de cada item — nome do produto, quantidade, preço unitário registrado no item, desconto e o subtotal do item (quantidade × preço − desconto). Pense em como percorrer simultaneamente os pedidos e seus respectivos itens.
Exercício 5 — Function: total de um pedido
Tipo de objeto: FUNCTION
Recursos PL/SQL exigidos: FUNCTION com RETURN, exceção nomeada
Crie a função cp3_fn_total_pedido(p_pedido_id IN NUMBER) RETURN NUMBER, que retorna o valor total do pedido somando todos os seus itens (quantidade × preco_unitario − desconto). Se o pedido informado não existir, a função deve lançar uma exceção customizada com mensagem clara. Esta função será reutilizada nos exercícios 8, 9 e 10.
Exercício 6 — Function: cálculo do frete
Tipo de objeto: FUNCTION
Recursos PL/SQL exigidos: FUNCTION com RETURN, condicional, agregação
A logística da ShopFast usa a tabela de frete a seguir:
Região / UF do endereço de entrega
Fórmula do frete
SP ou RJ
R$ 15,00 + R$ 2,00 × peso total (kg)
MG ou ES (demais estados do Sudeste)
R$ 20,00 + R$ 3,00 × peso total (kg)
Demais UFs do Brasil
R$ 30,00 + R$ 5,00 × peso total (kg)
Crie a função cp3_fn_calcular_frete(p_pedido_id IN NUMBER) RETURN NUMBER, que retorna o valor do frete de um pedido considerando a UF do endereço de entrega do pedido e o peso total dos produtos contidos nele. Se o pedido não existir, lance exceção. Esta função será reutilizada no exercício 8.
Exercício 7 — Procedure: movimentação de estoque
Tipo de objeto: PROCEDURE
Recursos PL/SQL exigidos: exceções customizadas, DML em duas tabelas
Crie a procedure cp3_pr_movimentar_estoque(p_produto_id IN NUMBER, p_tipo IN CHAR, p_qtd IN NUMBER, p_observacao IN VARCHAR2) que:
•  atualiza o saldo na tabela de estoque (tipo 'E' soma à quantidade; tipo 'S' subtrai);
•  registra a movimentação na tabela de histórico (cp3_movimento_estoque), com data atual;
•  lança exceção customizada quando: o produto não existe; a quantidade for ≤ 0; o tipo informado não for 'E' nem 'S'; ou a saída deixaria o estoque negativo.
A procedure será reutilizada nos exercícios 8 e 10. Use COMMIT apenas no final, após todas as operações concluídas com sucesso.
Exercício 8 — Procedure: finalizar um pedido
Tipo de objeto: PROCEDURE
Recursos PL/SQL exigidos: cursor explícito, chamadas a function/procedure, exceções, transação
Crie a procedure cp3_pr_finalizar_pedido(p_pedido_id IN NUMBER) que finaliza um pedido pendente, executando os seguintes passos em uma única transação:
1.valida que o pedido existe e está com status 'PENDENTE' (caso contrário, lança exceção apropriada);
2.percorre os itens do pedido com um cursor explícito e, para cada item, chama a procedure cp3_pr_movimentar_estoque do exercício 7 com tipo 'S' (saída) — qualquer falha deve abortar a finalização;
3.atualiza valor_total do pedido chamando a função cp3_fn_total_pedido (exercício 5);
4.atualiza valor_frete chamando a função cp3_fn_calcular_frete (exercício 6);
5.altera o status do pedido para 'FINALIZADO' e dá COMMIT.
Em caso de qualquer falha, faça ROLLBACK e relance a exceção com uma mensagem que indique o ponto da falha.
Exercício 9 — Procedure: classificação de clientes
Tipo de objeto: PROCEDURE
Recursos PL/SQL exigidos: cursores aninhados, chamada a function, condicional, DBMS_OUTPUT
A área de marketing precisa classificar a base de clientes ativos com base no volume comprado em pedidos FINALIZADOS. Crie a procedure cp3_pr_classificar_clientes que, para cada cliente ativo:
•  calcule o total gasto somando o resultado da função cp3_fn_total_pedido (exercício 5) para cada um de seus pedidos finalizados;
•  classifique conforme a tabela abaixo;
•  exiba via DBMS_OUTPUT: nome, e-mail, total gasto formatado em R$ e classificação.
Total gasto em pedidos finalizados
Classificação
≥ R$ 5.000,00
VIP
≥ R$ 1.000,00 e < R$ 5.000,00
REGULAR
> R$ 0,00 e < R$ 1.000,00
NOVO
Sem pedidos finalizados
INATIVO
Utilize cursor explícito para percorrer os clientes e, dentro do loop, outro cursor (também explícito) para percorrer os pedidos de cada cliente.
Exercício 10 — Procedure integradora: processar uma compra completa
Tipo de objeto: PROCEDURE
Recursos PL/SQL exigidos: orquestração, validações, exceções, transação, chamadas aos objetos anteriores
Esta é a procedure final do trabalho — ela orquestra o fluxo completo de uma compra no e-commerce. Crie cp3_pr_processar_compra(p_cliente_id IN NUMBER, p_produto_id IN NUMBER, p_qtd IN NUMBER, p_endereco_id IN NUMBER) que execute, em uma única transação:
1.validações iniciais — cliente existe e está ativo; produto existe e está ativo; endereço existe E pertence ao cliente informado; quantidade solicitada é positiva. Cada falha deve lançar exceção customizada específica;
2.criação do registro do pedido (status inicial 'PENDENTE', data atual, valor_total e valor_frete em zero);
3.criação do item do pedido com o preco_unitario congelado a partir do produto;
4.baixa de estoque chamando a procedure cp3_pr_movimentar_estoque (exercício 7);
5.finalização chamando a procedure cp3_pr_finalizar_pedido (exercício 8);
6.ao término, exibir via DBMS_OUTPUT um resumo: número do pedido criado, valor total, valor do frete e valor a pagar (total + frete).
Em qualquer falha, executar ROLLBACK de toda a operação e relançar a exceção. Nenhum registro parcial deve permanecer no banco em caso de erro.
